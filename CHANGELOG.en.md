# A-side module changelog

[中文](CHANGELOG.md)

## 1.7.11

- Ship two built-in keyboxes: `keybox_tee.xml` for the TEE level (the 001
  three-level chain) and `keybox_strongbox.xml` for the StrongBox level, both
  installed on the device. The levels no longer share a key, so a TEE request can
  no longer end up signed by the StrongBox self-signed chain.
- Online sources (server public pool, Yuri, AOSP) only update the TEE keybox; the
  StrongBox one can only be replaced from a file or restored from the bundle.
- Server-side minting: a security-level-2 request only uses the StrongBox identity
  pinned in the console and is refused when none is pinned instead of borrowing a
  TEE identity; source collectors never write the StrongBox identity.

- The local SOTER fallback now matches a real device: one ATTK, one ASK per uid
  (generated on first use and persisted), each ASK carrying its own AuthKeys.
  Previously every app shared a single ASK.
- No fixed key material is bundled any more: the ATTK is generated fresh (self-signed,
  timestamped) at every release build and then stays put in the binary unless a file
  replaces it; ASKs are never bundled and are generated on first use per uid.
- Callers only supply the ATTK (via WebUI or the built-in one); the ASK is
  generated by the module, so nothing extra has to be provided.
- Fixed every ommega route turning into SYSTEM_ERROR 4 after a screen-off/on cycle:
  an identity-less auth token is no longer rejected, and one business rejection no
  longer fail-closes mirror recovery for every route (PR #10).
- The per-uid SOTER ASKs and AuthKeys now live in a single file
  (/data/misc/keystore/ommega/soter_asks.json) instead of one pem per key, and
  AuthKeys survive a payload restart.
